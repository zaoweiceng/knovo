# 增量知识维护

先读取 [Markdown 协议](references/protocol.md) 和 [维护清单](references/maintenance.md)。输入为知识根目录以及可选的指定文件。打包后辅助脚本位于 `scripts/runtime/`，首次在该目录运行 `npm install --omit=dev`；源码仓库中使用根目录 `scripts/`。

## 处理边界

1. 运行 `node <runtime>/scripts/knowledge.mjs scan --root <知识目录>`。首次仅建轻量索引和基线，不分析全库正文。显式指定文件时加 `--files '["相对路径.md"]'`。
2. 只读取返回的变更及每项至多 10 个候选全文。每次最多 20 个变更项，余下留待下一次用户调用，不自动循环直到全库处理完毕。目录规模大不改变此边界。
3. 候选是比较对象，不是额外待整理清单。只为当前变更需要才改候选或直接反向关联；不递归扩展维护范围。
4. 无变化时报告“没有需要维护的增量”，不重写笔记。错误项解释原因，保留待处理。

## 判断与变更

- 同一概念、适用条件一致的重复内容才合并；保留独有例子、限定条件、来源和不同学习事件。保留最早创建的 ID，其他 ID 加入 `merged_from`，旧标题放入 `aliases`。删除源文件由 apply 自动备份归档。
- 互补主题建立 `related`，必要的前置理解放 `prerequisites`。依赖方向是被引用者为前置知识。关联只放元信息；不要向正文写索引列表。
- 多个独立问题拆成独立文件，原 ID 保留为简短且有实际内容的概览，关联新文件；不制造只有链接的空壳。
- 复用既有分类与标签；仅在增量所需时规范同义词，不大范围重排目录。
- 直接修复确定的拼写、格式或计算错误。外部事实优先核对官方/原始来源，记录链接、版本及核验日期；无法核实时保留原文并标记待核实。不要用模型记忆静默覆盖冲突结论。
- 删除项的引用不能凭空猜测新目标：存在明确 merged_from 映射时修正，否则保留失效声明并在报告中指出。

## 应用和恢复

生成维护清单，带每个文件读取时的 SHA-256；使用 `apply` 统一验证、锁定、备份及写入，不绕过脚本直接批量修改原文件。新的生成文件也必须纳入清单。更改 `updated_at`，但没有新的学习行为时不伪造学习事件。

发生并发冲突时重新读取受影响项，不用新的 hash 强行覆盖旧结果。失败项不标记 processed；完全无改动但已检查的增量通过 processed 确认，避免重复分析。

只检查模式可以 scan 和读取候选，输出建议，不执行 apply。扫描建立的隐藏缓存不属于内容变更。

执行后报告批次 ID、修改/合并/拆分数量、纠错依据、待核实项、失败项及剩余增量。仅将本次最终指纹标记已处理，未处理增量继续保留。

恢复使用 `restore --root <目录> --batch <批次ID>`；后续发生修改的文件必须人工/agent 检查冲突，不强制覆盖。进程异常留下锁时，`unlock` 只允许释放已不存在进程的锁；锁持有进程仍在时等待或报告。
